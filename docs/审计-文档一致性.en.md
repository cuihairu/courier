# Documentation-Code Consistency Audit (2026-10-13)

> Method: per the "Documentation and Source Code Consistency Audit Specification" — three discrepancy types (ahead / behind / mismatch) + six steps (enumerate → sample claims → gather code evidence → bucket → fix → closure).
> Evidence standard: every claim must point to a source file:line; negative conclusions require first verifying that the search paths exist; self-congratulatory completion reports and `- [x]` checkboxes are equally claims subject to audit.
> Fixes defer to the code: delete ahead-of-code claims or mark them "not implemented / planned", add missing descriptions, correct mismatched wording; never change code to accommodate the docs.
> Execution: five parallel audit agents (README bilingual / architecture+roadmap+index / layers+provider-guide+sdk-selection / implementation-status / contract 17 pages) plus the public facade (GitHub About / vitepress config); every finding was rechecked by the main agent against file:line before entering the tables.
