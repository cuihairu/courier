## D-001 F33 审计保留策略与查询面——推荐形态(2026-10-19)

**决定**:推荐接入方摄取形态 = 既有 `HTTPSink` 直写 → 接入方侧落库代理(**追加式,按日分区** JSONL 或对象存储前缀)→ 保留 **365 天**基线(法域/平台硬性要求优先,更长按需外移冷归档);查询与合规导出在**接入方侧只读面**完成,网关不含存储、不加查询端点。

**理由**:网关侧事件面 + 日志/直写双半边已全落(F33 仓内面,批次 62/65/66/102),剩余属举证基础设施,归部署面最省攻击面;365 天为 SOC 2 式举证常见基线,事件只含账号维度元数据(realname.md 数据红线)不放大个人信息风险。

**被否**:①网关内置 DB/表结构——违反「持久化随部署面」分层(provider-guide §5),且破网关零外部依赖口径;②网关暴露审计查询 API——契约外端点 + 新攻击面,举证数据不应经游戏网关出口;③保留天数写进契约——法域中立红线,阈值类不进契约(同 consent 阈值先例)。

**影响面**:provider-guide §4 realname 行补推荐摄取形态一句;todo.md F33 行已代决收口(真实接入仍随部署面)。

## D-002 F77 二期 Options Store 接缝——字节 blob 形状(2026-10-19)

**决定**:`teller.Options.Store` / `telleralt.Options.Store` = `OrderStore{ Load() ([]byte, error); Save([]byte) error }` **字节级全量快照**接缝;`ErrSnapshotMissing` = 首次启动哨兵(等价文件不存在),其余读错误与损坏字节同 fail-closed(HealthCheck → 503,不静默从空态启动丢单);优先级 **Store > StateFile > 纯内存**(同设时文件不读写);实现方须保证 Save 原子(写失败不产生半态)。

**理由**:接缝只交换字节、订单/账本结构与索引留在 Provider 内——两实现零新依赖、零新攻击面、零新 env(纯 Go API 注入),接入方 DB / Redis / 对象存储各写一个几行适配器即可接入;与一期 StateFile 语义(全量 + 原子 + fail-closed)完全同构,复用其全部测试语义。

**被否**:①逐订单 KV(Get/Put/Delete)——把订单键序/分片泄漏进接缝,适配面变大且两实现形状分歧;②事件账本 Append/Replay 接口——强制 teller(可变状态表)改事件模型,不对称;③内置 SQL/NoSQL 存储——引入仓库首个外部依赖,持久化归部署面。

**影响面**:teller/telleralt 接缝 + 6×2 测试(三代重启/优先级/首启哨兵/损坏快照/读故障/写故障);provider-guide §4 payments 行;todo.md F77 行二期收口,全项完成。

## D-003 F78 二期管理入口——不立项,SIGHUP 即终态(2026-10-19)

**决定**:配置重载入口以 `SIGHUP`(批次 99 一期)为**终态**;管理 HTTP 端点与文件监听均**不立项**。容器编排场景经 exec 注信号覆盖(docker exec / kubectl exec kill -HUP 1)。

**理由**:管理端点的前置(管理面鉴权契约)不存在——无鉴权的重载端点等于把配置注入做成攻击面;文件监听两形态分别破零依赖口径(fsnotify)与常驻后台复杂度(mtime 轮询),而 SIGHUP 已覆盖运营需要且失败语义(保留旧表)经 e2e 实证。

**被否**:①管理 HTTP 端点(如 POST /v1/admin/reload)——前置契约缺失,新攻击面;②fsnotify 文件监听——引入仓库首个外部依赖;③mtime 轮询(Ticker)——常驻 goroutine 换低频收益,不匹配。

**影响面**:todo.md F78 行二期收口(标注重载入口终态),全项完成;architecture/provider-guide 治理文本不变(SIGHUP 口径批次 99 已登记)。
